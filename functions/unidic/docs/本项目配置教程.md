# 本项目配置教程

> 本教程完成 Utaer 项目 unidic_and_f0 部分在 WSL 宿主上的 Python 环境、MeCab 依赖、环境变量与词典路径配置，并说明阶段二规则匹配库的自定义配置与扩展方法，使 `functions/unidic/init.py` 可以运行双阶段分析管线。

## 1. 文档简介

`tdmelodic 配置教程.md` 负责把 tdmelodic 及其组合词典装好；本教程负责把**项目自身**的宿主环境配好：

- `init.py` 需要宿主可用的 mecab-python3、组合词典路径（阶段一）；
- 阶段二的规则引擎按 `stage2_rules/` 模块与 `rules_config.json` 运行，本教程 3.8 说明如何自定义配置与扩展规则匹配库；
- 项目约定的 `test.env` 环境变量。

> **说明**：分析链路**不依赖 Docker 容器**——组合词典已安装在宿主，阶段一直接在宿主查表；docker 镜像仅在 `tdmelodic 配置教程.md` 的大词典推断阶段使用。

建议阅读顺序：`tdmelodic 配置教程.md` → `tdmelodic 使用教程.md`（可选）→ 本教程 → `本项目 unidic_and_f0 部分启动教程.md`。

## 2. 前置条件

### 2.1 环境与软件要求

- 已完成 `tdmelodic 配置教程.md`，且组合词典已安装在 `$(mecab-config --dicdir)/tdmelodic`。
- WSL2（Ubuntu-22.04），自带 python3 与 git。

### 2.2 文件与路径约定

- 项目根目录须包含 `test.env`（开发期环境变量文件，允许提交）与 `functions/unidic/` 下的 `init.py`、`stage1_analyzer.py`、`stage2_rules/`、`rules_config.json`、`Dockerfile`。
- 第三方仓库（`tdmelodic/`、`mecab-unidic-neologd/`）与 UniDic 基础辞书须已按 `tdmelodic 配置教程.md` 自行安装。
- 规则引擎的权威依据为项目根目录 `NHK/` 参考资料库（`UNIDIC_manual.pdf`、NHK 辞典摘录 13 篇、`Japanese_pitch_accent.htm`）。

### 2.3 前置文档依赖

- `tdmelodic 配置教程.md`（必读前置）。
- 项目总规范 `AGENTS.md` §6（`test.env` 路径约定）。
- `AGENT.md`（模块准则，了解双阶段架构与规则可追溯要求）。

## 3. 核心步骤

### 3.1 安装 pip

```bash
sudo apt update
sudo apt install python3-pip
```

### 3.2 安装 mecab-python3

```bash
pip install mecab-python3
```

> **说明**：安装后在 Python 中以 `import MeCab` 使用（对应 `stage1_analyzer.py` 的写法）。

### 3.3 补全 mecab 相关包

```bash
sudo apt install -y mecab libmecab-dev mecab-ipadic-utf8
```

> **说明**：`libmecab-dev` 是 mecab-python3 的编译/运行依赖；`mecab-ipadic-utf8` 提供系统默认词典（不指定 `-d` 时使用）。

### 3.4 建立 mecabrc 软链接

```bash
sudo mkdir -p /usr/local/etc && sudo ln -s /etc/mecabrc /usr/local/etc/mecabrc
```

> **说明**：mecab-python3 运行时会在 `/usr/local/etc/` 下查找 mecabrc 配置文件，而系统 mecab 的配置位于 `/etc/mecabrc`，因此建立软链接指向它。

### 3.5 PATH 配置（可省略）

```bash
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

> **说明**：使 pip 用户级安装的可执行文件能被直接调用。

### 3.6 环境变量与路径约定（test.env）

项目根目录的 `test.env`（后缀即 `env`）内容：

```ini
TEST_USER_ID=testuser123
TEST_AUDIO_ID=20030303123749
TEST_SAVE_PATH=fast-api\audio\
```

约定（总 AGENTS.md §6）：

- `functions/` 下各独立功能只需读取这三个值，拼接为 `fast-api\audio\testuser123\20030303123749\` 即为开发期处理后文件的保存路径。
- `TEST_AUDIO_ID` 采用「日期 + 6 位随机数」格式（如 `20030303123749`），与 Supabase Storage 布局一致。
- 后续接入 fast-api / supabase 时，只需修改引用这三个值所在区域的代码。
- 保存路径一律引用 `test.env`，禁止硬编码路径。
- 本模块在该目录下产出 `audio_accent.json`（分析结果）与 `rule_report.json`（规则概要报告）。

### 3.7 词典路径确认

```bash
mecab-config --dicdir
```

输出即 MeCab 词典根目录（如 `/usr/lib/x86_64-linux-gnu/mecab/dic`）。`stage1_analyzer.py` 会在该目录下拼接 `/tdmelodic`，因此组合词典必须位于 `<dicdir>/tdmelodic`。确认：

```bash
ls $(mecab-config --dicdir)
```

输出中应包含 `tdmelodic` 目录。

### 3.8 阶段二规则匹配库的配置与扩展

规则引擎由 `stage2_rules/` 下的规则模块与 `rules_config.json` 共同驱动：

```text
functions/unidic/
├── stage2_rules/
│   ├── __init__.py         # 规则注册表：按优先级加载全部规则
│   ├── base.py             # Rule 基类（match / apply / priority / source_ref）
│   ├── compound.py         # 复合词规则
│   ├── conjugation.py      # 活用形规则
│   ├── particles.py        # 付属語接続规则
│   ├── nucleus_legality.py # 核合法性规则（特殊拍核移位，后处理校验型）
│   ├── multi_unit.py       # 多单位/句级规则
│   └── fallback.py         # 兜底规则
└── rules_config.json       # 规则优先级/开关配置
```

#### 3.8.1 调整规则优先级与开关（rules_config.json）

```jsonc
{
  // 默认优先级：核合法性（后处理校验）> 活用形 > 复合词 > 付属語 > 数詞 > 多单位 > 語種倾向兜底 > 默认平板
  "rule_overrides": {
    // 覆盖某条规则的优先级（数值越大越先匹配）
    "R-PART-NO-ODAKA": { "priority": 95 },
    // 关闭某条规则
    "R-FALLBACK-HEIBAN": { "enabled": false }
  },
  // 自定义规则目录（可选；其中的规则会被注册表自动加载）
  "custom_rules_dir": "stage2_rules/custom"
}
```

> **注意**：`nucleus_legality.py` 是后处理校验型规则（核不允许落在 ン・ッ・ー・二重母音副音・無声化拍之后），其优先级应始终高于其他推导型规则；调整优先级时勿将其置后。

#### 3.8.2 新增自定义规则

1. 在 `stage2_rules/custom/`（或直接 `stage2_rules/`）下新建 `my_rule.py`；
2. 继承 `Rule` 基类，实现 `match()`（条件判断）与 `apply()`（改写调型），并填写 `priority` 与 `source_ref`（资料编号 + 节号，如 `NHK Ⅲ-1 2.1`）：

```python
# stage2_rules/custom/my_rule.py
from stage2_rules.base import Rule

class MyCustomRule(Rule):
    rule_id = "R-CUSTOM-MYRULE"
    name = "自定义规则示例"
    source_ref = "自定义（依据：NHK Ⅲ-1 2.1）"
    priority = 70          # 数值越大越先匹配；默认各模块优先级见 rules_config.json

    def match(self, morphs, i):
        # 确定性条件判断，禁止推测；返回 True 才触发
        return morphs[i].pos.startswith("名詞") and morphs[i].accent_raw == "@"

    def apply(self, morphs, i):
        # 改写调型并登记到规则报告
        morphs[i].accent = 0  # 例：默认平板（实际规则请按资料逻辑编写）
        return morphs[i]
```

3. 将新规则登记进注册表 `stage2_rules/__init__.py`（或依赖 `custom_rules_dir` 自动加载）；
4. 用启动教程 4.2 的验证样例确认新规则被触发且出现在 `rule_report.json` 中。

> **约束**：规则必须是**确定性条件判断**；不得调用 `tdmelodic-s2ya`/`-sy2a` 等推测功能；每条规则必须带 `source_ref`。

## 4. 验证方式

### 4.1 Python 绑定验证

```bash
python3 -c "import MeCab; print(MeCab.Tagger().parse('すもももももももものうち'))"
```

预期：正常输出若干行「表層形<Tab>品詞…」的分词结果（使用默认 ipadic 词典），无报错即表示 mecab-python3 安装成功。

### 4.2 词典路径验证

```bash
mecab-config --dicdir
ls $(mecab-config --dicdir)
```

预期：第一条命令输出词典根目录路径；第二条命令的输出中包含 `tdmelodic`。

### 4.3 规则库加载验证

```bash
cd Utaer/functions/unidic/
python3 -c "from stage2_rules import registry; print([r.rule_id for r in registry])"
```

预期：按优先级顺序打印全部已注册规则的 `rule_id`，且自定义规则出现在列表中；`rules_config.json` 中被关闭的规则不出现。

## 5. 常见问题 / 排错

| 症状 | 原因 | 解决方案 |
|---|---|---|
| `pip: command not found` | python3-pip 未安装 | 回到 3.1 |
| `pip install mecab-python3` 编译失败 | 缺少 libmecab-dev | 先执行 3.3 再重试安装 |
| `import MeCab` 报 mecabrc 相关错误 | 软链接缺失 | 回到 3.4 |
| `Permission denied` | 需要管理员权限的步骤未加 sudo | 检查 3.3、3.4 的 sudo |
| `ls $(mecab-config --dicdir)` 无 `tdmelodic` | 组合词典未安装 | 完成 `tdmelodic 配置教程.md` 3.16 |
| 自定义规则未出现在 `rule_report.json` | 未登记进注册表，或 `match()` 条件未命中 | 回到 3.8.2 第 3 步；对照 4.3 检查注册表 |
| 两条规则命中同一形态素且结果冲突 | 优先级配置错误 | 检查 `rules_config.json` 的 `rule_overrides` |
| 核合法性规则被覆盖 | `nucleus_legality` 优先级被调低 | 恢复其后处理校验型规则的最高优先级（3.8.1 注意） |
