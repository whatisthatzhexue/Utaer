# 引擎使用文档 — 双阶段声调分析引擎的操作手册

> 本文档说明**怎么操作本引擎**，重点回答两个问题：
> 1. **怎么获得 NHK 音调结果**（东京式声调／下がり目记号 ＼・━）；
> 2. **怎么获得 JSON 产物**（`audio_accent.json` / `rule_report.json`）。
>
> 引擎实现为**双阶段确定性管线**：阶段一 tdmelodic 组合词典确切匹配（禁止调型推测）
> → 阶段二规则引擎（资料二 UniDic 表9/10/12＋资料三 NHK Ⅰ/Ⅱ/Ⅲ 系列＋资料四
> 东京式理论）。同一输入必得同一输出，结果可复现。
>
> 相关文档：环境安装见《本项目配置教程.md》《tdmelodic 配置教程.md》；
> 产物格式契约见《本项目 unidic_and_f0 部分启动教程.md》与 `AGENT.md`。

## 0. 前置条件（一次配置即可）

- WSL2（Ubuntu-22.04）已按《本项目配置教程.md》装好宿主 `mecab-python3`；
- 组合词典已安装在 `$(mecab-config --dicdir)/tdmelodic`（见《tdmelodic 配置教程.md》3.16）；
- 项目根目录 `test.env` 存在（三个开发期路径值，见下文 §2.2）。

自检确认环境可用（可选但推荐）：

```bash
cd Utaer/functions/unidic
python3 selfcheck.py        # 全绿 = 环境与规则引擎均正常
```

## 1. 快速开始（两条命令）

所有命令均在 **`Utaer/functions/unidic/` 目录下**执行：

```bash
cd Utaer/functions/unidic

# ① 分析一句话（控制台打印 NHK 音调结果 + 两个 JSON，并自动写盘）
python3 init.py --text "米を盛る"

# ② 从文件批量分析（每行一句，UTF-8）
python3 init.py --input test_sentences.txt
```

运行结束后：

- **NHK 音调结果** → 看控制台的「规则概要报告」段（每个アクセント単位带 ＼/━/・
  记号）与「分析结果」段的 `accent` 数字，见 **§2**；
- **JSON 产物** → 自动写盘到 `fast-api/audio/<user-id>/<audio-id>/`，见 **§3**。

## 2. 怎么获得 NHK 音调结果

### 2.1 操作：运行 CLI，看三段输出

```bash
python3 init.py --text "米を盛る"
```

控制台依次打印三段（下方为真实输出）：

**第 1 段：阶段一原始解析**（词典确切匹配的原始数据，调型来自词典）

```text
===== 阶段一：词典基础分析（确切匹配，禁止推测）=====
米	コメ	コメ	米	名詞-普通名詞-一般			2
を	オ	ヲ	を	助詞-格助詞
盛る	モル	モル	盛る	動詞-一般	五段-ラ行	終止形-一般	0
EOS
```

- 列为：表層形 / 発音 / 読み / 原型 / 品詞 / 活用型 / 活用形 / **調型**
- 調型列的取值：数字（`0`=平板，`N`=第 N 拍后下降）、逗号多调型（如 `0,1`）、
  `@`=词典未收录（交由兜底规则处理，**不会用推测补齐**）

**第 2 段：`audio_accent.json`**（分析结果——每词调型＝**NHK 声调核位置**数字）

```text
===== 分析结果 audio_accent.json（东京式声调）=====
{
  "input": "米を盛る",
  "json_data": [
    { "idx": 0, "morph": "米", "morph_reading": "コメ", "accent": 2, ... },
    { "idx": 1, "morph": "を", "morph_reading": "オ",  "accent": 0, ... },
    { "idx": 2, "morph": "盛る", "morph_reading": "モル", "accent": 0, ... }
  ]
}
```

**第 3 段：`rule_report.json`**（规则概要报告——`result` 列即 **NHK 记号渲染**）

```text
===== 规则概要报告 rule_report.json（成功匹配并触发的规则清单）=====
{
  "input": "米を盛る",
  "matched_rules": [
    { "rule_id": "R-LEX-DICT",   ..., "target": [0,0], "result": "コメ＼" },
    { "rule_id": "R-PART-FLAT",  ..., "target": [0,1], "result": "コメ＼オ" },
    { "rule_id": "R-LEX-DICT",   ..., "target": [2,2], "result": "モル━" },
    { "rule_id": "R-MULTI-UNIT", ..., "target": [0,2], "result": "コメ＼オ・モル━" }
  ]
}
```

### 2.2 结果怎么看：NHK 记号解读

| 记号 | 含义 |
|---|---|
| `＼` | **下がり目**（声调核）位置——插在核拍之后，表示其后下降 |
| `━` | **平板型**（该アクセント単位无下降核），标在単位末尾 |
| `・` | **アクセント単位的分界**（NHK 複数単位表记） |

**要整句的 NHK 音调结果 → 取 `R-MULTI-UNIT` 规则的 `result`**（单位间以 ・ 分隔），
如 `コメ＼オ・モル━` 读作：「米を」（コメ＼オ，尾高＋不干渉付属語）＋「盛る」（モル━，平板）。

**要单词的 NHK 音调结果 → 取该词的 `accent` 数字**，换算规则：

| accent | 型 | NHK 记号示例（4 拍词） | 含义 |
|---|---|---|---|
| `0` | 平板型 | `カラオケ━` | 无下降核 |
| `1` | 頭高型 | `カ＼ラオケ` | 第 1 拍后下降 |
| `N`（0<N<拍数） | 中高型 | `カラ＼オケ`（N=2） | 第 N 拍后下降 |
| `N`＝拍数 | 尾高型 | `カラオケ＼` | 末拍后下降（接付属語时核显现） |

引擎输出的调型已按**东京式**体系逐条推导：词典直取 → 复合词（表10 C1–C5）→
名词/动词/形容词/活用形接续（NHK Ⅲ 系列＋表12 F 系列＋表9）→ 核合法性校验 →
多単位切分。每条结论都可追溯到 `rule_report.json` 的 `source_ref`（依据出处）。

### 2.3 更多输入形式

```bash
# 文件中每行一句（UTF-8 编码）
python3 init.py --input 歌詞.txt

# 覆盖保存位置（不改 test.env）
python3 init.py --text "住民税を払います。" --user myuser --audio-id 20261012000001

# 只要音调结果、不产出规则报告
python3 init.py --text "米を盛る" --no-report
```

## 3. 怎么获得 JSON

### 3.1 方式 A：CLI 自动写盘（最常用）

`python3 init.py ...` 在打印的同时**自动写出两个 JSON 文件**，位置由项目根目录
`test.env` 的三个值拼接（禁止硬编码）：

```ini
# Utaer/test.env
TEST_USER_ID=testuser123
TEST_AUDIO_ID=20030303123749
TEST_SAVE_PATH=fast-api\audio\
```

实际路径：`Utaer/fast-api/audio/<TEST_USER_ID>/<TEST_AUDIO_ID>/`

| 文件 | 内容 |
|---|---|
| `audio_accent.json` | 分析结果（逐词表記/读音/调型/变体/振假名，§7.4 格式） |
| `rule_report.json` | 规则概要报告（六字段命中规则清单） |

运行末尾会打印写入位置，例如：

```text
[INFO] 产物已写入：/home/rainybread/Utaer/fast-api/audio/testuser123/20030303123749
```

**校验 JSON 合法**：

```bash
cd Utaer
python3 -m json.tool fast-api/audio/testuser123/20030303123749/audio_accent.json
python3 -m json.tool fast-api/audio/testuser123/20030303123749/rule_report.json
```

**多行文本**（`--input`）：逐行分析后合并为**一份** JSON——`idx` 全句连续递增、
规则 `target` 区间同步平移。

### 3.2 方式 B：Python API（供 FastAPI 等程序调用）

```python
# 在 Utaer/functions/unidic/ 目录下（或将该目录加入 sys.path）
from pipeline import run_pipeline

# 纯内存调用：返回 (audio_accent_json, rule_report_json)
accent_json, rule_report = run_pipeline("米を盛る")
print(accent_json["json_data"][0]["accent"])   # 2

# 指定保存目录时同时写盘（目录不存在会自动创建）
run_pipeline("米を盛る", save_dir="fast-api/audio/testuser123/20030303123749")

# 不要报告
accent_json, _ = run_pipeline("米を盛る", write_report=False)
```

需要**阶段一原始解析行**（控制台第 1 段的内容）时用完整入口：

```python
from pipeline import run_pipeline_full

result = run_pipeline_full("米を盛る")
result.accent_json    # dict：分析结果
result.rule_report    # dict：规则报告（write_report=False 时为 None）
for line in result.raw_lines:   # 阶段一 Tab 分隔原始行（含结尾 "EOS"）
    print(line)
```

### 3.3 方式 C：文件→JSON 批量流水

```bash
cd Utaer/functions/unidic
python3 init.py --input test_sentences.txt --user testuser123 --audio-id 20261012000001
# → fast-api/audio/testuser123/20261012000001/audio_accent.json （12 句合并结果）
```

## 4. JSON 结构速查

### 4.1 `audio_accent.json`（总规范 §7.4）

```jsonc
{
  "input": "米を盛る",                    // 原始输入文本
  "json_data": [
    {
      "idx": 0,                           // 形态素序号（从 0 开始；多行文本全句连续）
      "morph": "米",                      // 表記形（显示用）
      "lemma": "米",                      // 辞書形
      "morph_reading": "コメ",            // 读音（片假名；前端注音基础）
      "pos": "名詞*普通名詞*一般",         // 词性（层级以 * 分隔）
      "accent": 2,                        // 【核心】东京式核位置：0=平板；N=第N拍后下降
      "variants": [],                     // 词典多调型的其余值（首个为主值）
      "ruby_pairs": [["米", "こめ"]],      // 振假名对齐（[null, かな]=无对应表记）
      "notes": ["词典未收录"]              // 可选：仅未收录等情形出现
    }
  ]
}
```

### 4.2 `rule_report.json`

```jsonc
{
  "input": "米を盛る",
  "matched_rules": [
    {
      "rule_id": "R-PART-FLAT",           // 规则唯一标识
      "name": "平板式付属語・基本接続",     // 规则名
      "source_ref": "NHK Ⅲ-1 1.1（『付属語不干渉』）",  // 依据出处（可追溯）
      "target": [0, 1],                   // 作用的形态素 idx 闭区间
      "logic": "「を」为平板式付属語……",    // 命中逻辑（中文说明）
      "result": "コメ＼オ"                // NHK 记号渲染（＼核/━平板/・単位）
    }
  ]
}
```

**常用规则 ID 速查**：

| rule_id | 作用 |
|---|---|
| `R-LEX-DICT` | 词典直取（含 `@`＋`[]` 解码词） |
| `R-COMPOUND-C1…C5` | 复合词四型（表10 结合型公式） |
| `R-PART-FLAT / KIFUKU / DECIDING / NO-ODAKA / TA-TE` | 名词接付属語（NHK Ⅲ-1） |
| `R-CONJ-MOD` | 活用形修饰型（表9）＋命令形 |
| `R-NUCLEUS-SPECIAL` | 核合法性校验（核移位，最高优先级校验遍） |
| `R-MULTI-UNIT` | 整句多単位切分（**整句 NHK 记号在这里**） |
| `R-NUM-TWO-UNIT` | 数詞 2単位語（15/14/19） |
| `R-COMPOUND-NAME-TITLE` | 个人名＋肩書き不复合 |
| `R-DECOMP-LEX` | 未收录整词的确定性再切分 |
| `R-FALLBACK-*` | 語種倾向兜底（词典未收录时的最后手段） |

## 5. 配置定制入口（可选）

规则引擎的行为由 `functions/unidic/rules_config.json` 控制，常改两项：

```jsonc
{
  "homograph_overrides": {                 // 同形語修正表：词典与预期不一致时的确定性修正
    "米":  { "reading": "コメ", "pron": "コメ", "accent_raw": "2" },
    "日本": { "reading": "ニホン", "pron": "ニホン", "accent_raw": "2" }
  },
  "rule_overrides": {                      // 按 rule_id 改优先级 / 禁用
    "R-FALLBACK-HEIBAN": { "enabled": false }
  },
  "compound": { "nhk_flat_exceptions_priority": true },  // NHK 平板例外表优先
  "resegment": { "enabled": true }                        // 未收录整词再切分开关
}
```

自检内附配置机制验证（禁用/优先级/自定义规则目录），修改后可跑
`python3 selfcheck.py` 确认无回归。

## 6. 常见操作问答

**Q1：我只想要一句话的 NHK 音调记号，最省事的做法？**
```bash
cd Utaer/functions/unidic && python3 init.py --text "句子"
#  控制台最下方 rule_report 段里 R-MULTI-UNIT 的 result 即整句 NHK 记号
```

**Q2：怎么拿到 JSON 而不是控制台刷屏？**
用 Python API（§3.2）：`run_pipeline("句子")` 直接返回 dict；
或运行 CLI 后读 §3.1 路径下的文件。

**Q3：换用户/音频目录（正式接入 Supabase 布局前）？**
`--user <id> --audio-id <id>` 覆盖 `test.env`，路径布局与
`audio/<user-id>/<audio-id>/` 一致。

**Q4：某词结果不对怎么办？**
1. 先看 `rule_report.json` 的 `source_ref` 确认为哪条依据；
2. 词典推断条目的偏差点 → 在 `rules_config.json` 的 `homograph_overrides`
   加一条确定性修正（如 `"コーヒー": {"accent_raw": "3"}`）；
3. 规则逻辑问题 → 提 issue/PR（每条规则都带可追溯依据）。

**Q5：批量回归测试？**
```bash
python3 selfcheck.py      # 125+ 项断言（NHK 原文例逐字对照、确定性、不变量……）
```

## 7. 排错速查

| 症状 | 原因 | 解决 |
|---|---|---|
| `[ERROR] 输入文本为空` | `--text ""` | 传入非空文本 |
| `[ERROR] 输入文件不存在` | `--input` 路径错 | 检查路径；文件需 UTF-8 |
| `组合词典目录不存在：…/tdmelodic` | 词典未装 | 《tdmelodic 配置教程.md》3.16 |
| `未安装 mecab-python3` | 依赖缺失 | `pip install mecab-python3` |
| 输出乱码 | 终端编码 | 使用 UTF-8 终端（脚本已自动设 stdout UTF-8） |
| 某词调型为 `@` 或 notes「词典未收录」 | 该词大音调词典未收录 | 正常路径：走語種倾向兜底；可用同形語修正表补精确值 |
| 结果与预期差 1 拍 | 词典读法差异（如 ニッポン/ニホン） | 用 `homograph_overrides` 指定标准读法 |

退出码：`0`=成功；`1`=输入/环境错误（错误信息打印到 stderr）；`2`=自检时环境缺失。
